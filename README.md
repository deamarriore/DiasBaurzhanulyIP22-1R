## 🚀 Как запустить проект

### 1. Активировать виртуальное окружение

```powershell
.\venv\Scripts\Activate.ps1
```

### 2. Запустить сервер

```powershell
python manage.py runserver
```

Сервер будет доступен по адресу: **http://127.0.0.1:8000/**  
Корень сайта перенаправляет на веб-интерфейс бухгалтерии: **http://127.0.0.1:8000/accounting/**

### 3. Инициализировать план счетов (бухгалтерия)

После первого запуска создай счета (демо-план в стиле РК):

```powershell
python manage.py init_accounting
```

Опционально — загрузить демо-проводки и документы (нужны пользователь в БД и хотя бы один товар):

```powershell
python manage.py init_accounting --with-demo
```

### 4. Войти в веб-интерфейс бухгалтерии

Открой **http://127.0.0.1:8000/accounting/** и войди тем же пользователем, что и в админке (например `admin` / `admin123`), либо через **http://127.0.0.1:8000/accounts/login/**

В интерфейсе доступны: реализация, закупки, касса/банк, журнал проводок, отчёты (ОСВ, главная книга, ОПУ, баланс). Документы **реализации** и **закупки** при проведении автоматически создают складские операции (`StockOperation`).

### 5. Открыть админку Django

Перейди по ссылке: **http://127.0.0.1:8000/admin/**

## 📊 Структура Базы Данных

### 1. **Category (Категория товара)**
- **Поля:**
  - `name` — Название категории (уникальное)
  - `created_at` — Дата создания (автоматическое)
- **Уже созданы:** Электроника, Мебель, Канцтовары, Одежда, Инструменты

### 2. **Supplier (Поставщик)** ⭐ НОВОЕ
- **Поля:**
  - `name` — Название поставщика (уникальное)
  - `contact_person` — Контактное лицо
  - `phone` — Телефон
  - `email` — Email адрес
  - `address` — Адрес доставки
  - `created_at` — Дата создания (автоматическое)
- **Уже созданы:** 4 готовых поставщика с реальными контактами

### 3. **Product (Товар)** ⭐ КЛЮЧЕВАЯ МОДЕЛЬ
- **Поля:**
  - `name` — Название товара
  - `article` — Артикул (уникальный)
  - `category` — Категория (внешний ключ → Category)
  - `supplier` — Поставщик (внешний ключ → Supplier) ⭐ НОВОЕ
  - `description` — Описание товара
  - `price` — Цена в рублях
  - **`current_quantity`** — Текущее количество на складе
  - **`min_threshold`** — Критический остаток (минимум, по умолчанию 10) ⭐ НОВОЕ
  - `created_at` — Дата создания (автоматическое)
  - `updated_at` — Дата последнего обновления (автоматическое)

- **Методы:**
  - `is_low_stock()` — Проверяет, ниже ли количество критического остатка
  - `get_stock_status()` — Возвращает статус запасов (❌ Нет, ⚠️ Низко, ✅ OK)

- **Индексы для оптимизации:**
  - По артикулу (article)
  - По категории (category)

### 4. **StockOperation (Журнал операций)** ⭐ АВТОМАТИЗАЦИЯ
- **Поля:**
  - `product` — Товар (внешний ключ → Product)
  - `operation_type` — Тип операции (выбор: "Приход" или "Расход")
  - `quantity` — Количество товара
  - `reason` — Причина/Примечание операции
  - `created_at` — Дата и время операции (автоматическое)
  - `created_by` — Пользователь, выполнивший операцию (внешний ключ → User)

- **Автоматизация (метод `save()`):**
  - ✅ При добавлении операции типа **"Приход"** → количество в Product **УВЕЛИЧИВАЕТСЯ**
  - ✅ При добавлении операции типа **"Расход"** → количество в Product **УМЕНЬШАЕТСЯ**
  - ✅ **Валидация:** Система проверяет, достаточно ли товара перед расходом
  - ✅ Если недостаточно → выдаёт ошибку "Недостаточно товара на складе"

- **Индексы для оптимизации:**
  - По товару и дате (product, -created_at)
  - По дате (created_at)

## 🧪 Как протестировать автоматизацию

### Тест 1: Приход товара

1. **Перейди в Админка → Products**
2. **Добавь новый товар:**
   - Название: "Ноутбук ASUS"
   - Артикул: "ASU-001"
   - Категория: "Электроника"
   - Поставщик: "ООО Электросервис"
   - Цена: 50000
   - Минимум: 5
   - **Количество будет 0 по умолчанию**

3. **Перейди в Админка → Stock Operations**
4. **Добавь операцию:**
   - Товар: выбери "Ноутбук ASUS"
   - Тип: **"Приход"** ⬆️
   - Количество: 50
   - Примечание: "Приход от поставщика ООО Электросервис"

5. **Проверь результат:**
   - Вернись в Products
   - **Количество товара должно быть 50!** ✅

### Тест 2: Расход товара

1. **В Stock Operations добавь новую операцию:**
   - Товар: "Ноутбук ASUS" (уже 50 шт.)
   - Тип: **"Расход"** ⬇️
   - Количество: 20
   - Примечание: "Продажа клиенту ООО Рога и Копыта"

2. **Проверь результат:**
   - Вернись в Products
   - **Количество должно быть 30!** ✅
   - Статус: ✅ OK (30 > 5)

### Тест 3: Критический остаток (низкий запас)

1. **Добавь ещё одну операцию расхода:**
   - Количество: 26 (чтобы осталось 4)

2. **Проверь статус в Products:**
   - **Должно быть: ⚠️ Низко (4 шт.)**
   - Цвет оранжевый

### Тест 4: Попытка перерасхода (валидация)

1. **Добавь операцию расхода:**
   - Товар: "Ноутбук ASUS" (осталось 4 шт.)
   - Количество: **10** (больше, чем есть)

2. **Результат:**
   - **Система выдаст ошибку!** ❌
   - Сообщение: "Недостаточно товара на складе. Доступно: 4 шт., требуется: 10 шт."
